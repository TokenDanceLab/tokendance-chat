# TokenDanceChat Security Risk Register

Last reviewed: 2026-07-31

TokenDanceChat is a demo and AgentHub stack validation app. The risk target is to keep it safe as a public demo while avoiding accidental drift into production identity or messaging infrastructure.

## Scope

- Backend REST/WebSocket/OIDC/media/webhook: `backend/`
- Frontend/PWA/service worker: `frontend/`
- Deployment and docs: `Dockerfile*`, `docker-compose.yml`, `docs/`, `README.md`, `SECURITY.md`

## Recent Mitigation Evidence

- 2026-05-25: `CHAT-SR-001` was mitigated in repo by adding local session tokens on login/register, registering the HTTP handler as the Hub's session verifier, checking `Store.UserExists` during WS join, and sending the session token from login/register UI paths.
- 2026-05-25: `CHAT-SR-002` was mitigated in repo by adding `SearchMessagesForUser`, wiring `/api/search` to the authenticated session username, filtering deleted messages in search, and adding store/handler regression coverage for private/deleted-result leakage.
- 2026-05-25: `CHAT-SR-017` was mitigated in repo by checking group membership in `/api/export?conversation=group:<name>` before store export and adding regression coverage for both non-member denial and member export.
- 2026-05-25: `CHAT-SR-005` and `CHAT-SR-019` were mitigated in repo by moving webhook secrets out of URLs into `Authorization: Bearer`, adding body/content limits, rejecting query-string secrets, persisting accepted webhook messages with real group message IDs, using group-member fanout, and using a server-derived webhook sender.
- 2026-05-25: `CHAT-SR-006` was mitigated in repo by replacing direct OIDC provider calls with a bounded `http.Client`, adding response body caps, adding capacity/backpressure and cleanup lifecycle handling to OIDC state/redeem token stores, adding OIDC endpoint rate limits, parsing trusted reverse-proxy client IPs, and pruning expired rate-limit IP entries.
- 2026-05-25: `CHAT-SR-015` was partially mitigated by sanitizing `docs/handoff-report-2026-05-25.md`, README/deploy examples, and OIDC compose examples so they record deployment contracts and local/placeholder verification commands instead of private topology details.
- 2026-05-25: `CHAT-SR-009` was mitigated in repo by making Service Worker `/api/*` requests network-only and bumping `CACHE_NAME` to `tdchat-v5`, preventing authenticated REST responses from being persisted in Cache Storage.
- 2026-05-25: `CHAT-SR-021` was mitigated in repo by replacing global chat-message broadcast with room-scoped fanout and adding a regression that a client in `room-2` does not receive a `room-1` message or `mention_all`.
- 2026-05-25: `CHAT-SR-016` was mitigated in repo by preserving unauthenticated public preview as a bounded latest-message sample, capping anonymous `limit` to 20, requiring an app session for `before` pagination, and keeping authenticated pagination behavior covered by handler regressions.
- 2026-05-25: `CHAT-SR-010` was mitigated in repo by moving CORS and WebSocket origin checks onto a shared parser, requiring explicit scheme-bearing allowlist entries, rejecting `*` for cross-origin requests, and adding regressions for host/port mismatches, wildcard subdomains, bare domains, and unexpected ports.
- 2026-05-25: `CHAT-SR-007` was mitigated in repo by giving link preview fetches a guarded `DialContext` that validates the final resolved IP immediately before TCP connect and refuses DNS-rebinding-style private address pivots before the underlying dialer runs.
